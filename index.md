# **Reflections on Markdown** 
#### By Gavin Jones
1. *To indicate document structure, Markdown uses ASCII punctuation characters. A steam-oriented, hierarchical document model implies when the format is able to handle things like paragraphs, headers, lists, links, emphasis, and code, but struggles with things like tables, footnotes, and metadata. Formal specification allows anyone to write Markdown without having to learn a complete syntax. However, it can also leave many edge cases undefined.*
2. *The consequences of using regular expressions rather than a formal grammar is that it can cause inconsistent behavior across implementations. It can also cause performance vulnerabilities. Prioritizing the human reader of the source file helps it relate to the parsing ambiguities that later motivated CommonMark.*
3. *Gruber's emphasis on borrowing conventions from email, usenet, and earlier plain text formats reveals that it was key to shaping the way communities would work to become infrastructural. This was because the use of blockquotes with >, emphasis with asterisks, and setext headers.*
4. *Markdown has exceeded far beyond its design for web writers. It has now spread into note-taking, documentation, academic writing, and AI training data/output. Open standards and simplicity allow people to adapt them into unplanned, new problems.*
6. The contrast between Markdown (given away, BSD license) and Scribe (sold, time-bombed) represents different political economies of software. What conditions enabled Gruber to give Markdown away? What does the gift economy of open source depend on that we might not see?
